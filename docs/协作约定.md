# 协作约定

本文件记录**用户明确要求的固定做法**，每次改动都必须遵守。
与「开发依据」无关的内容不放这里 —— 那些在 `PRD.md`。

---

## 1. 每次改动完，回复底部必须给出安装包路径 ⭐

用户要求（v1.2 之后生效）：

> 每次改动完在对话底部都要显示安装包路径

**执行方式**：任何一次涉及代码改动的回复，**结尾固定附上**当前可安装的 APK 路径，
用代码块包起来方便复制。格式：

```
D:\desk\自律app\dist\自律-v<版本>-release.apk
```

配套要求：

- 交付文件名**必须带版本号**（`自律-v1.2-release.apk`），不要用固定的 `自律-release.apk`
  —— 否则用户分不清手上是哪个版本
- 升版本时同步：`versionCode` / `versionName` / `dist` 文件名 / `verify-apk.ps1` 的版本断言
- 旧版本的 dist 文件要删掉，避免用户拿错
- 同时说明：包名是否变化、能否覆盖安装、数据是否保留

## 2. 改动必须配测试

- 每个改动都要有对应的有效测试；无法测试的部分要**明说无法验证**
- 测试失败先定位根因，**区分"代码错"还是"测试写错"**并在回复里讲清楚
- 严禁删测试、跳过测试、放宽断言来让测试通过

## 3. 诚实汇报验证状态

- 真机相关的一律标注 **PENDING**，不要含糊过去
- 没验证的事就说没验证，不要用"应该没问题"这种措辞

## 4. 工具使用上的硬约束（踩过的坑，别再踩）

| 约束 | 原因 |
| --- | --- |
| **不要用管道调用 `run-tests.ps1` / `verify-apk.ps1`** | 脚本内部 `exit`，管道会挂死 |
| 含中文的 `.ps1` 必须 **UTF-8 带 BOM** | PowerShell 会把无 BOM 的按 GBK 读，中文全乱 |
| PowerShell 里改文件时，here-string **不要直接内联进方法调用** | 会被解析成多余参数，替换静默失败 |
| 改完文件要**验证**（统计关键标识出现次数 / 看行号），不要假设替换成功 | 已多次遇到静默失败 |
| 用脚本批量改代码时先**规范化换行符** | 插入 CRLF 而原文件是 LF 会导致锚点不匹配 |
