## 2. M1 · 环境搭建（逐条可执行）

### T1.1a · 路径风险预检 【必须先做】

**为什么**：工作区路径含中文（E7）。Java、Gradle、aapt2、D8 对非 ASCII 路径的容忍度不一致，一旦踩到，报错信息会非常难懂（常表现为"找不到文件"或乱码）。

**做法**：
1. 先按原路径走完 T1.2，执行 `java -version` 和一段"在中文路径下编译并运行一个 .java 文件"，确认 JDK 正常
2. T1.7 编译 APK 时如果出现路径相关的诡异错误，立刻执行下面的后备方案

**后备方案**（二选一）：
- **A**：把整个项目移到 ASCII 路径（如 `D:\desk\zilv-app\`），并把工作区切过去 —— **推荐**，一次解决
- **B**：在 ASCII 路径建目录联接（junction），从那里构建：`cmd /c mklink /J D:\zilv D:\desk\自律app`

> ⚠️ 两种方案都需要在工作区外写文件，会触发一次权限审批。**这是可接受的**——总比跟编译器的乱码报错缠斗好。

**验收**：能明确回答"中文路径到底有没有问题"。

### T1.1 · 目录骨架 + 下载器

**产出**：目录树（§1.3）+ `tools/fetch.mjs` + `tools/env.ps1`

**`tools/fetch.mjs`**（替代不可用的 curl）：

```javascript
// tools/fetch.mjs —— 用法: node tools/fetch.mjs <url> <输出文件>
import { createWriteStream } from 'node:fs';
import { mkdir } from 'node:fs/promises';
import { dirname } from 'node:path';
import { Readable } from 'node:stream';
import { pipeline } from 'node:stream/promises';

const [url, out] = process.argv.slice(2);
if (!url || !out) { console.error('用法: node tools/fetch.mjs <url> <输出文件>'); process.exit(2); }

await mkdir(dirname(out), { recursive: true });
const res = await fetch(url, { redirect: 'follow' });
if (!res.ok) { console.error(`HTTP ${res.status}  ${url}`); process.exit(1); }

const total = Number(res.headers.get('content-length') || 0);
let done = 0, lastPct = -1;
const body = Readable.fromWeb(res.body);
body.on('data', c => {
  done += c.length;
  if (total) {
    const pct = Math.floor(done / total * 100);
    if (pct !== lastPct && pct % 5 === 0) {
      lastPct = pct;
      process.stdout.write(`\r  ${pct}%  ${(done / 1048576).toFixed(1)} / ${(total / 1048576).toFixed(1)} MB`);
    }
  }
});
await pipeline(body, createWriteStream(out));
process.stdout.write('\r');
console.log(`完成  ${out}  ${(done / 1048576).toFixed(1)} MB`);
```

**验收**：`node tools\fetch.mjs https://dl.google.com/android/repository/repository2-1.xml .cache\test.xml` 能下到 375 KB 的文件。

## 5. 工作循环建议

每个任务按这个节奏走，避免"写一大堆再一起调"：

```
1. 确认上一个任务已验收
2. 改代码
3. gradle assembleDebug（增量，看耗时是否正常）
4. adb install -r
5. 真机走一遍这个任务的验收项
6. 通过 → 记一行变更日志 → 下一个任务
   不通过 → 修，回到 3
```

**每个任务结束记一行变更日志**（追加到 `docs/变更日志.md`）：
```
2025-08-14  T4.7  拦截联动完成。抖音被盖住。遗留：小窗模式未测。
```

**约定**：
- 一次只做一个任务，不要并行改多个模块——真机验证成本高，串行更容易定位问题
- 涉及计算逻辑的（连续天数、距离、窗口调度）**先写单元测试再写实现**
- 任何"先这样，以后再改"的地方，立刻记进 `docs/技术债.md`，不要留在脑子里
