版本：v1.0
上游文档：[需求规格说明书 v1.3](需求规格说明书.md)、[通知脱敏可行性调研](../通知脱敏可行性调研.md)
目标设备：Android 14（API 34）
文档状态：**IA 与交互设计阶段**

---

## 1. 个人自用版的裁剪说明

本 App 只给一个人用。以下内容**明确砍掉**，不进入设计：

| 砍掉 | 原因 |
| --- | --- |
| 多用户 / 账号体系 | 不需要 |
| 云同步 / 服务器 | 本地 Room 数据库足够 |
| 分享、好友监督、排行榜 | 不需要 |
| 上架合规相关的隐私政策页、权限说明弹窗 | 侧载自用 |
| 精致的首次引导动画、空状态插画 | 自己知道怎么用 |
| 成就徽章、积分等级、补卡券 | v1.0 不做 |
| 多语言 | 只做简体中文 |

**保留但只能简化、不能砍的**：

- ✅ **权限向导必须做** —— 侧载 + Android 13+「受限设置」是硬门槛，不做就是一片灰开关，你自己也会懵
- ✅ **数据导出/备份** —— 个人自用没人帮你恢复数据，丢了就是丢了
- ✅ **权限体检页** —— 权限会静默失效（尤其国产 ROM），需要一眼看到

## 2. 设计原则

1. **打开即见状态。** 首页第一屏必须回答"现在锁着吗 / 还有多久 / 我今天打卡了没"。
2. **遮挡层是唯一强交互面。** 锁机期间用户注意力都在遮挡层上，它必须是最好用的那一屏。
3. **报告用来照镜子，不用来羞辱。** 复盘数据陈述事实，不加"你又失败了"这类评判文案。
4. **弱化配置，强化日常。** 个人自用，规则设一次就不改了，所以配置全塞进设置 Tab，首页只放高频动作。
5. **不炫技。** Material 3 默认组件 + 一套克制的配色，不做自定义动效。


### 3.2 导航结构

- **底部导航栏，3 个 Tab**：今天 / 记录 / 设置
- 无侧滑抽屉、无二级 Tab
- 详情页用系统返回键返回；遮挡层没有返回键，只有屏幕上的按钮

### 3.3 全局布局规范

- 顶部：无 AppBar 标题栏（首页用大标题直接写"今天"），详情页用返回箭头 + 标题
- 安全区：底部导航栏 + 侧边手势区留白
- 单位：8dp 栅格；卡片圆角 16dp；页面左右边距 16dp
- 字体：系统默认（思源黑体 / Roboto），标题 28sp，正文 16sp，次要信息 14sp

## 4. 页面详设

### 4.1 权限向导

**目的**：把一个侧载的 App 从"什么都没权限"变成"能干活"。

**结构**：一屏一步，顶部固定进度指示 `3/9`，底部固定「下一步」按钮（未完成时按钮文案变为「去开启」）。

```
┌──────────────────────────────┐
│  ←  设置权限              3/9 │
├──────────────────────────────┤
│                              │
│   ⬤⬤⬤○○○○○○                │
│                              │
│   ## 第 3 步：无障碍服务       │
│                              │
│   这是拦截功能的核心。          │
│   没有它，App 无法知道          │
│   你现在打开了哪个应用。        │
│                              │
│   ⚠️ 如果开关是灰的：          │
│   先回到「应用信息」页，        │
│   点右上角 ⋮ →               │
│   「允许受限设置」，再回来。    │
│                              │
│   ┌────────────────────┐     │
│   │  文字步骤图（截图）   │     │
│   └────────────────────┘     │
│                              │
│   当前状态：● 未开启           │
│                              │
├──────────────────────────────┤
│      [   去开启   ]           │
└──────────────────────────────┘
```

**9 步顺序**（顺序有依赖，不可乱）：

| # | 步骤 | 为什么排这个位置 |
| --- | --- | --- |
| 1 | 通知权限 | 后面所有通知的基础 |
| 2 | **允许受限设置** | **必须最先做**，否则 3/4/9 的开关都是灰的 |
| 3 | 无障碍服务 | 拦截核心 |
| 4 | 悬浮窗权限 | 遮挡层核心 |
| 5 | 精确闹钟 | 窗口触发 |
| 6 | 电池优化白名单 | 保活 |
| 7 | 自启动 / 后台运行 | 国产 ROM，图文指引 |
| 8 | 前台定位 | 打卡校验 |
| 9 | 通知使用权 | 通知脱敏；**唯一可以跳过的一步** |

**交互**：
- 每一步进入前检测状态；已完成的步骤自动跳过
- 全部完成后进入首页
- 底部有「稍后再说」（除第 2、3、4 步外都可跳过）
- 每一步的「去开启」直接 `startActivity` 跳系统页，**返回时自动复检状态**并打勾

### 4.3 锁机结束报告（新需求 · 设计重点）

**入口**（三个，同一个页面）：
1. 窗口结束时的通知：`图书馆自习结束 · 你用了 51 分钟手机` → 点击进入
2. 首页的「昨天回顾 / 上次回顾」卡片
3. 记录 Tab → 锁机历史 → 点任意一条

**页面设计**

```
┌──────────────────────────────┐
│  ←  图书馆自习                 │
│      8月14日 08:00 – 18:00     │
├──────────────────────────────┤
│                              │
│  ┌─────────┐ ┌─────────┐    │
│  │ 10 小时  │ │ 51 分钟  │    │
│  │ 锁机时长 │ │ 用手机   │    │
│  └─────────┘ └─────────┘    │
│                              │
│  打卡                         │
│  ┌──────────────────────────┐│
│  │ ✅ 09:12 到图书馆          ││
│  │    迟到 1 小时 12 分       ││
│  └──────────────────────────┘│
│                              │
│  关键应用使用时长              │
│  ┌──────────────────────────┐│
│  │ 微信    ████████████ 47 分 ││
│  │ 支付宝  █            3 分  ││
│  │ 相机    ▏            1 分  ││
│  └──────────────────────────┘│
│                              │
│  被拦住的                     │
│  ┌──────────────────────────┐│
│  │ 抖音        27 次          ││
│  │ 小红书       5 次          ││
│  │ 王者荣耀      3 次          ││
│  └──────────────────────────┘│
│                              │
│  异常                         │
│  ┌──────────────────────────┐│
│  │ 14:23 紧急放行（招商银行）  ││
│  └──────────────────────────┘│
│                              │
│  [ 导出本次记录 ]             │
└──────────────────────────────┘
```

**数据来源与口径**（必须写清楚，否则数字没意义）：

| 字段 | 口径 |
| --- | --- |
| 锁机时长 | 窗口开始 → 窗口结束（含已解锁的时段） |
| 用手机 | 窗口内本设备屏幕点亮且非锁屏的总时长，由无障碍服务采集 |
| 关键应用使用时长 | 窗口内各 App 在**前台**的累计时长；**只列有时长的 App**，按降序，最多 8 个 |
| 被拦住的 | 窗口内尝试打开白名单外 App 的**次数**（同一 App 连续尝试 5 秒内合并为 1 次） |
| 异常 | 紧急放行、无障碍被关闭、悬浮窗被撤销、系统时间被修改 |

**交互细节**：
- 「关键应用使用时长」的条形图按最大值等比缩放，最短的条也保留可见宽度
- 被拦住的条目可点击 → 跳转到拦截日志页并筛选该 App
- 如果窗口内没打卡：「打卡」区块显示 `❌ 本次未打卡`
- 如果是"仅定时解锁"的规则：不显示打卡区块
- 如果窗口内没有任何使用记录：显示 `这段时间你没碰手机 👏`（唯一的正向文案）

**为什么不做成自动弹全屏**：Android 后台启动 Activity 受限，且我们已取消强制弹窗。用通知 + 首页卡片，用户主动点开，体验更好也更省心。

### 4.6 锁机遮挡层（Overlay）

这是全 App 最关键的交互面。它不是 Activity，是 `TYPE_APPLICATION_OVERLAY` 全屏窗口。

```
┌──────────────────────────────┐
│                              │
│            🔒                │
│                              │
│         还有 48:12            │
│                              │
│   ┌──────────────────────┐  │
│   │ 「去图书馆，别在这     │  │
│   │    刷手机」            │  │
│   └──────────────────────┘  │
│                              │
│   ┌──────────────────────┐  │
│   │      立即打卡          │  │
│   └──────────────────────┘  │
│                              │
│   ┌──────────────────────┐  │
│   │      返回桌面          │  │
│   └──────────────────────┘  │
│                              │
│         紧急放行 5 分钟        │
│                              │
└──────────────────────────────┘
```

**必须处理的交互细节**：

| 场景 | 行为 |
| --- | --- |
| 点「立即打卡」 | 移除遮挡层 → 启动打卡页（本 App 在内置白名单，不会被拦） |
| 点「返回桌面」 | 移除遮挡层 → 回桌面（`GLOBAL_ACTION_HOME`） |
| 点「紧急放行」 | 弹二次确认 `放行后本次锁机对 <App> 失效 5 分钟，会记入报告` → 确认后放行并计入事件 |
| 规则是"仅定时解锁" | **不显示**「立即打卡」，只留「返回桌面」 |
| 用户按 Home 键 | 桌面在白名单里，正常回桌面，遮挡层移除 |
| 来电 / 闹钟 / 系统对话框 | 遮挡层必须**主动让路**（监听窗口变化，`TYPE_SYSTEM` 等非应用窗口出现时隐藏） |
| 分屏 / 小窗模式 | 遮挡层覆盖被拦 App 所在的区域（**需真机测试可行性**） |
| 用户反复点被拦 App | 每次重新盖住，同时记一次拦截计数（5 秒内合并） |

**视觉**：深色背景（接近纯黑，降低刺激）、大号倒计时、无动画（避免炫技也避免耗电）。

## 5. 关键交互流程

### 5.1 一次完整的锁机窗口

```
07:45  通知「15 分钟后开始锁机，到三教一楼打卡可免除」
07:45  首页状态卡变橙：⏳ 15 分钟后开始锁机
08:00  无障碍开始拦截；首页状态卡变深色：🔒 锁机中
08:14  用户点开抖音 → 遮挡层盖住 → 记录拦截 #1
08:15  用户点「返回桌面」→ 遮挡层消失 → 回到桌面
08:20  用户下拉通知栏，看到「微信 · 有新消息」（脱敏生效）
09:12  用户到三教一楼，在遮挡层点「立即打卡」→ 校验通过
09:12  首页状态卡变绿：✅ 已解锁 · 今日不再拦截
18:00  窗口结束 → 通知「图书馆自习结束 · 你用了 51 分钟手机」
18:01  用户点通知 → 打开锁机结束报告
```

### 5.2 打卡解锁的判定

```
点「立即打卡」
  └→ 取一次定位（超时 15 秒）
       ├→ 精度 > 门槛 → 「信号弱，请到空旷处重试」[重试]  ← 不计失败
       │    └→ 连续 3 次失败 → 显示降级通道
       └→ 精度达标 → 算 Haversine 距离
            ├→ 距离 > 半径 → 「还差 340 米」+ 方向箭头
            └→ 距离 ≤ 半径 → 打卡成功 → 解除本次拦截 → 写库
```

## 7. 文案规范

| 场景 | 用 | 不用 |
| --- | --- | --- |
| 复盘报告 | `你用了 51 分钟手机` | `你失败了` / `自制力太差` |
| 拦截计数 | `点了 27 次抖音` | `你又刷了 27 次` |
| 未打卡 | `本次未打卡` | `你放弃了自己` |
| 零使用 | `这段时间你没碰手机 👏` | — |
| 紧急放行 | `会记入报告` | `这是作弊` |
| 锁机中 | 用户自定义文案 | 系统评判性文案 |

**原则：只陈述事实，不做道德评判。** 报告是照镜子，不是挨骂。
